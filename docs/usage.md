# 觅途 Mitu 使用指南

本指南对应源码版本 `3.1.0`。管理页面为 `http://localhost:6866/boss/`，后端 API 端口为 `9527`。当前以 Windows 本地单用户环境为主，定时投递、账号注册和多人服务尚未实现。

## 源码构建与运行

准备 Java 21、Node.js 22 或兼容版本、npm、Google Chrome，以及可用的前端依赖。Next.js 16 要求 Node.js 至少为 20.9.0；项目实际使用本机 Chrome，而非仅凭 Java 环境即可投递。

首次启动前必须准备包含正确表结构的 `db/getjobs.db`。当前 `sql.init.mode=never`，没有完整空库初始化；缺少 `boss_config` 等表会导致启动失败。升级时保留已有数据库和 `browser-data/`，不能用空文件代替数据库，也不要分享带有个人配置和登录资料的数据库。

全新环境的依赖安装仍待验收：`front/pnpm-workspace.yaml` 中部分 `allowBuilds` 值仍是字符串占位，包管理器版本也尚未固定。应先规范相关配置并完成依赖准备；这里不把 `pnpm install` 描述为已经验证的一键安装步骤。

### 开发运行

在项目根目录执行。以下命令以有效数据库、前端依赖及可下载构建依赖的网络已经准备好为前提：

```powershell
.\gradlew.bat bootRun
```

`bootRun` 会依赖前端构建和 Patchright driver 安装，并设置 driver 路径与 Node 运行环境。首次下载依赖需要网络；代理按个人 Gradle 配置管理。

### 打包运行

```powershell
.\gradlew.bat installPatchrightDriver

Push-Location front
node node_modules/next/dist/bin/next build
node node_modules/typescript/bin/tsc --noEmit
node scripts/copy-dist.mjs
Pop-Location

.\gradlew.bat bootJar

$env:PLAYWRIGHT_NODEJS_PATH = (Get-Command node.exe).Source
$mituDriver = (Resolve-Path .\build\patchright-driver).Path
java "-Dplaywright.cli.dir=$mituDriver" -jar .\build\libs\mitu-3.1.0.jar
```

`bootJar` 不会自动安装 Patchright driver，driver 的 `package/cli.js` 必须存在。运行时保持项目工作目录、数据库及浏览器资料路径正确；只复制 JAR 不代表所有运行条件已经齐全。静态管理页面随后端提供，不需要照搬旧 `front/start-prod.mjs` 入口。

## 第一次投递

1. 启动本地服务，打开投递工作台，在项目浏览器中完成 Boss 登录。
2. 填写关键词、城市和职位类型。多个关键词使用逗号分隔；城市“不限”表示全国。职位类型始终只选一项，“不限”也是独立选项。
3. 在“沟通内容 → 编辑”中填写自己的固定招呼语。开启 AI 后，固定招呼语仍作为生成失败的备用内容。
4. 设置搜索岗位上限与本次投递上限，确认静默模式已保存，再点击“开始投递”。开始操作会先保存当前表单；保存失败不会启动。
5. 从工作台查看进度，需要时停止。协作式停止会等待当前操作和清理结束，状态确认结束后再启动下一次任务。

薪资、经验、学历、公司条件与 HR 活跃筛选在“高级偏好”中。黑名单独立管理，添加和删除立即生效。配置草稿离页前应先保存。

## 搜索与投递数量

搜索上限按开始检查的候选岗位计数，包含过滤、跳过和详情失败。投递上限按尝试发起沟通计数，发起后发送失败仍计入；成功发送自定义消息另有结果统计。

两个数量跨关键词和城市累计，达到任意一项上限即停止；`0` 表示该项不限。它们约束单次任务，不统计当天在平台内外已使用或剩余的沟通名额。

## 固定招呼语

在“沟通内容”中切换固定信息或 AI 模式。AI 的服务地址、模型及密钥在“系统设置”中准备，提示词及个人介绍在“AI配置”中设置。

固定信息支持较长文本，页面允许最多 2000 字。Boss 首条招呼存在长度限制；兼容路径可能先触发平台默认问候，再进入聊天页发送完整文本，默认问候出现不代表自定义文本已经发送成功。若不希望默认问候先发送，应检查 Boss 账号自身的自动招呼设置。

不要把“尝试沟通”数量等同于“固定信息成功”数量。真实平台的页面及协议可能变化，实际发送结果仍需按记录核对。

## 静默与人工接管

工作台的“静默投递”默认开启，模式单独保存于 `work/quiet-delivery/settings.json`。存在未保存模式草稿时不能启动；运行期间不能更改。

“无感化自动投递”指复用投递页、最小化本项目 Chrome，在后台处理常规操作。它保留有界面浏览器，不代表没有窗口、进程或所有场景都零弹窗。

“查看浏览器”和“继续后台”只控制本项目浏览器，不会启动任务。请求在当前浏览器操作结束后的检查点执行，以状态确认结果。登录失效或出现人工验证时暂停；查看浏览器处理后再继续后台，不自动解决验证码。

实现和本地模拟验证范围见 [静默运行说明](quiet-delivery-plan.md)。

## JD 岗位库与需求总结

从左侧进入“JD岗位库”。岗位通过当前筛选后、沟通前独立保存，不以投递成功为条件；同一岗位去重，正文变化保留版本。可按关键词、实际城市、搜索类型和命中日期筛选，或勾选指定岗位应用范围，再查看原文、统计或导出 JSON/Markdown。

历史岗位通过“导入历史JD”显式导入，默认标记为匹配未确认；可人工纳入或排除，原投递记录和配置保留。

本地统计反映文字提及；AI总结展示覆盖率、证据、样本范围与过期状态。自动分析默认关闭；启用后将JD文本分批发往已配置的AI服务，按关键词、城市和类型分组，在达到阈值或任务结束时更新。分析与采集独立，可停止，支持有限重试与重启恢复。

当前提供需求总结和简历准备建议，不自动导入或改写简历，也不会补出没有实际获取的JD。完整约定见 [JD留存与总结说明](jd-collection-plan.md)。

## 统计与导出

“岗位统计”提供投递记录和分布分析。先编辑筛选，再点击“应用筛选”；分页、刷新和导出使用已应用条件。记录完整字段可从详情查看。

## 笔试练习助手

独立入口为 `http://localhost:6866/exam-assistant/`。支持题目输入、PNG/JPEG本机OCR、显式AI解析和Windows桌面窗口，不复用Boss投递队列。

- 图片不超过5 MiB、单边4096像素、1200万像素；识别后先校对，再生成解析。
- 图片OCR在本机执行。点击生成解析后，题目文本发送到系统设置中配置的AI服务。
- 桌面功能需要Windows 10 2004或更高版本及可用的OCR语言组件。首次启动会用系统.NET Framework编译器生成伴随进程。
- 进程名称为1–48位英文字母、数字、下划线或短横线，首位字母，不填`.exe`；改设置前先关闭桌面窗口，下次启动生效。
- `Ctrl+Alt+Shift+Enter`或桌面“截图识题”仅进行本地识别，范围为鼠标所在整块屏幕；生成解析仍由显式操作触发。
- 捕获排除只作用原生桌面窗口，不作用网页，也不保证覆盖所有录屏或共享方式；不把它描述为隐身或监考不可检测。

桌面设置位于 `work/desktop-assistant/settings.json`，题目与解析保存在服务会话内存，网页草稿位于标签页 `sessionStorage`；截图识别结束后清理临时图片。

## 本地资料与升级

保留 `db/` 和 `browser-data/`。数据库、浏览器资料、Cookie、简历、密钥、日志及备份不应进入公开仓库；JD和AI连接设置同样按个人资料管理。

当前本机单用户接口未完成多人服务统一鉴权，不直接公开6866/9527端口。公网账号、设备配对和定时投递的设计见 [后续实施路线](automation-multiuser-roadmap.md)。
