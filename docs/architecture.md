# 觅途 Mitu 架构

## 应用边界

招聘投递只支持 Boss 直聘，不注册其他招聘平台的控制器、配置服务、任务服务或数据库映射。另提供独立笔试助手，不操作 Boss 浏览器或投递队列。旧数据库中的历史表和 Cookie 记录不主动删除。

项目名称为 `mitu`，版本为 `3.1.0`，产品品牌为“觅途 Mitu”。Java 包名继续采用 `com.getjobs`，SQLite 文件与浏览器资料路径沿用已有部署，以兼容用户配置、登录态和投递记录。代码源自上游项目，保留其许可与版权说明。

机器人通知模块已移除，不注册 `Bot` 发送组件。系统设置只提交 `BASE_URL`、`API_KEY`、`MODEL`；通用配置接口路径保持不变，旧 `HOOK_URL`、`BOT_IS_SEND` 配置不再暴露或接受写入。历史配置行仍保留在数据库中，不做破坏性迁移。

## 关键模块

- `front/app/boss/page.tsx`：投递工作台，负责表单、登录状态、投递进度和启停操作。
- `front/app/boss/analysis/`：岗位及投递记录统计。
- `front/app/ai-config/`、`env-config/`：AI 提示词与服务设置。
- `front/lib/brand.ts`、`front/server.config.js`：统一产品名称、版本；`front/app/components/` 与 `components/ui/` 提供导航、品牌标志、页面框架和视觉组件，主题定义位于 `globals.css`。
- `BossController`、`BossConfigController`、`BossAnalyticsController`：Boss 任务、配置及记录接口。
- `LoginStatusController`：Boss 登录状态 SSE；兼容地址 `/api/jobs/login-status/stream`。
- `BossService`：配置、筛选字典、黑名单和投递数据。
- `BossJobService`：单次投递任务与停止状态；启动前校验配置。
- `BossQuietService`、`BossQuietController`：默认开启的静默模式、受控 Chrome 窗口状态及仅本机的 `/api/boss/quiet/*` 控制接口；静默设置独立保存。
- `Boss`：搜索、过滤、逐岗位沟通及数量上限。
- `PlaywrightManager`：Boss 页面、登录 Cookie、串行执行队列、浏览器生命周期和登录监控。
- `BossConfigSchemaInitializer`：为已有配置表幂等补齐单次任务上限字段。
- `BossJdStore`：最终筛选后的 JD 归档、版本与搜索命中来源、按范围去重取样、关键词统计、历史待确认导入。
- `BossJdAnalysisService`：独立持久化队列、逐版本 AI 提取缓存、原文证据与精确聚合、自动分组总结、取消和重启恢复。
- `BossJdController`、`front/app/boss/jd/`：仅本机的 `/api/boss/jd/*` 与岗位原文/需求总结页面；查询不会启动浏览器或调用模型。
- `front/app/exam-assistant/page.tsx`、`front/lib/exam-assistant.ts`：笔试题目、识别、解析和桌面设置管理。
- `ExamAssistantService`、`ExamAssistantController`：`/api/exam/recognize` 与 `/solve`，本地图片 OCR、独立文本 AI 请求；读取系统 AI 连接配置，不使用 Boss 的个人介绍或招呼语模板。
- `ExamDesktopService`、`ExamDesktopController`：`/api/exam/settings` 与 `/desktop/*`，Windows 伴随进程的编译、启动、关闭、内容同步与用户触发识题。
- `src/main/resources/desktop/MituDesktop.cs`、`recognize-image.ps1`：随 JAR 打包的 WinForms 窗口及 Windows OCR 脚本，Java 与桌面通过继承的标准输入/输出交换 JSON，不开放额外监听端口。

## 执行约束

浏览器操作通过 Playwright 专用线程串行执行。投递期间暂停后台登录监控，避免不同线程同时操作页面；启动 API 不允许缺少关键词或固定备用招呼语。

任务从浏览器初始化开始原子占用运行状态，清理完成后才释放，避免重复启动。停止等待超过 15 秒仅警告，继续保留运行状态和停止标志；阻塞的浏览器操作返回并完成清理后才允许下一任务。工作台订阅进度 SSE，终态以只读状态接口为准，防止 SSE 完成提示早于后台清理而提前释放按钮。

工作台状态轮询采用单请求与操作版本保护，忽略启停前已发出的迟到响应；保存使用当前表单快照，不重新加载整个配置，黑名单只刷新独立列表。`front/lib/boss-form.ts` 统一配置组装及数量/启动校验，保存快照只在内存中比较，不记录敏感配置内容。

统计页区分编辑中的筛选与已应用筛选；`front/app/boss/analysis/filters.ts` 统一查询条件、校验、页码与 CSV 转义。列表和统计请求可取消，并忽略过期响应；刷新只调用查询接口，不调用包含数据库整理操作的 reload 接口。

数量上限按整次任务累计。搜索数量包含过滤与失败；沟通尝试在点击前占用数量，异常不退还。成功发送招呼语另外统计。普通模式在岗位结束后回收本次新增页面；静默模式保留任务专用详情/聊天页，只清理岗位临时附属页，任务结束时统一回收专用页。两种模式均保留搜索页。

固定招呼优先通过 Boss 同源首条招呼协议发送。协议失败或文本超过 Boss 首条招呼限制时，先执行 Boss 原生默认沟通，再在实际聊天页面的可见编辑器中发送完整固定信息；输入兼容 `textarea` 与 `contenteditable`，并回读聊天记录确认。任务结果分别记录固定信息成功数和默认招呼兜底数，避免把默认消息误报为固定招呼成功。

当搜索关键词属于 AI 方向时，详情页会进行岗位相关性判断：标题需体现 AI 信号及明确技术、应用或产品职责，教育泛产品实习、销售、社媒、运营、课程、讲师等偶然包含 AI 的岗位会被跳过。普通关键词沿用 Boss 原始搜索结果；详情接口缺少 AI 字段时保留候选。

本地验证优先使用动态代理浏览器与临时 SQLite 数据库，不访问招聘者或调用真实投递接口。真实发送必须有用户明确指定的搜索条件、消息内容及发送授权。

笔试接口仅接受本机请求，存在 Origin 时需匹配本机觅途端口。截图只由显式按钮或快捷键触发；OCR 不联网，生成解析按钮才调用已配置的外部 AI。上传限制 PNG/JPEG、5 MiB、单边4096像素/1200万像素；识别和模型调用有并发及总超时限制，错误不暴露密钥或上游响应体。

桌面为独立、正常可枚举的原生进程，名称来自保存的配置，固定保留 Mitu 产品标识；同一项目只运行一个桌面窗口。设置修改前需关闭窗口；应用退出关闭自己的伴随进程。捕获排除使用 `SetWindowDisplayAffinity`，状态以系统调用实际结果为准，只作用于原生窗口，不作用于网页，不保证覆盖所有录屏、共享或监考机制。

## 数据与部署

保留 `db/getjobs.db` 与 `browser-data/`；数据库和 Cookie 不纳入发布源码。运行日志、诊断夹具和备份位于 `work/`，也不纳入源码。

笔试模块不迁移数据库，桌面设置独立保存在 `work/desktop-assistant/settings.json`，GET默认设置不落盘。桌面题目、解析仅在服务内存中保存，网页草稿保存在当前标签页的 `sessionStorage`；临时上传和桌面截图在本地识别结束后清理。首次启动桌面从 JAR 提取源码并编译到本地受控目录，无需下载安装面灵客户端。

Java 构建使用 `bootJar`，前端使用 `next build` 与 `scripts/copy-dist.mjs`。重新复制静态文件会清理旧平台导出；同时确认 JAR 中不存在已移除平台的类，防止增量构建残留。

静态服务将有效页面路径（含尾斜杠）映射到同名导出文件，不存在的页面返回 404。

本地访问管理页面 `http://localhost:6866/boss/`，API 为 `http://localhost:9527/api/`。应用启动不自动执行投递。

## 静默投递与人工接管

静默模式默认开启，仍使用有界面的 Chrome 和现有持久化上下文。`BossQuietService.begin()` 核实本项目窗口并最小化；任务通过后台建页创建专用详情/聊天页，`Boss` 在岗位间复用该页，避免逐岗创建和销毁。页面所有权区分搜索页、专用页和受控页面打开的临时页，不按标题操作无关浏览器，也不全局改写 `window.open`。页面异常、任务停止和最终清理均应释放任务专用引用及监听器。

HTTP 显示/后台接口只登记控制意图并返回已接收，实际窗口操作仍在原 Playwright 专用线程执行。活跃任务在安全检查点消费意图，空闲时通过已有执行队列调度；状态接口返回 `quiet` 的模式、窗口状态、待执行动作和人工处理提示。不能在 HTTP 线程并发访问 Playwright，或让浏览器控制同步等待整个投递任务结束。

识别登录或验证页面后进入人工等待，不继续执行下一次沟通；用户显式显示浏览器并处理后，再请求恢复后台。验证仍存在时拒绝恢复；停止信号和等待异常均结束人工等待并清理相关引用，不重放已发起的沟通步骤。该流程与原有发送计数、JD留存及协作式停止保持独立。

设置文件为 `work/quiet-delivery/settings.json`；缺文件时读取默认开启值但不落盘，保存时原子替换，损坏配置不能被默认值静默覆盖。修改设置与任务启动共享运行状态检查，任务启动、运行及清理期间禁止变更。

定时计划、注册登录、云端任务派发和多用户数据隔离尚未实施，设计见 `docs/automation-multiuser-roadmap.md`；当前接口与全局浏览器仍按本机单用户运行，不能直接作为多人公网服务开放。静默功能说明及实际验证范围见 `docs/quiet-delivery-plan.md`。

## JD 留存和总结

`Boss` 在取得详情并通过最终过滤后归档 JD，再沿用原有沟通流程；JD 指标通过 Boss 状态返回，与搜索/投递计数独立。归档失败明确计数但继续既有任务。采集传递不可变文本和筛选快照，后台分析不接收 Playwright 对象；快照排除招呼语、密钥和聊天记录。

新增表为 `boss_jd_job`、`boss_jd_version`、`boss_jd_match`、`boss_jd_extraction`、`boss_jd_report`、`boss_jd_settings`、`boss_jd_collection`。前三者分别保存岗位、正文版本和搜索命中，后四者保存提取缓存、固定报告、独立设置和自动调度状态。初始化幂等且失败仅将JD模块标为不可用，不删除或重建原有业务表。

岗位按Boss岗位ID去重，正文hash复用版本；A→B→A会重新指向A且计为版本更新。搜索范围按原始关键词精确匹配和命中时间选取对应最新版本，每岗位仅一次；搜索类型与详情实际类型分别保存，缺失详情类型标为未核验。历史默认未确认，人工纳入明确保留来源。排除和版本更新使对应报告过期。

本地词典仅统计文字提及，AI结构化要求必须包含可逐字回查的原文。提取缓存按版本/模型/提示词版本隔离，全文分段且不静默截断；报告保存全部样本版本清单、准确分母及覆盖率。模型调用有超时、响应大小及逐报告调用预算，预算在发送前落盘，重启不重置。自动模式默认关闭，启用后按关键词、实际城市和搜索类型分组更新；查询不触发分析。
